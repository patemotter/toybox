# Verifying a Toybox change

All Toybox verification scripts auto-serve the repository locally (no separate `http-server` process required; pass `PORT=<port>` only if you want a specific port) and pre-set safety-gear session flags.

## 1. Local verification pass

Run the unified verifier on the pages you changed:
```bash
node tools/verify.js <page1.html> [page2.html ...]
```
- Runs `check-site.js` (offline `sw.js` `CORE` check), `check-rules.js` (offline, API & shell invariants), `lint.js` (ESLint correctness), `smoke.js` (load/drag/error/scroll), and `shot.js` (screenshots).
- **For layout, panel, header, or new UI changes**, include `--all-sizes` to capture upright phone (`390x844`), sideways phone (`844x390`), and iPad sizes (`820x1180`, `1180x820`, `1024x1366`):
  ```bash
  node tools/verify.js --all-sizes <page1.html> [page2.html ...]
  ```

## 2. Inspect screenshots & test interactions

- **Always open and view** every screenshot generated by `verify.js` / `shot.js`: check that nothing overflows or clips, the title fits on one line, the whole machine stays on screen, and no labels collide.
- To verify a specific interaction without writing a custom script, use `tools/shot.js` with `--do` steps (`tap:`, `drag:`, `click:`, `wait:`, `eval:`, `shot:`):
  ```bash
  node tools/shot.js <page.html> --do "tap:..." --do "wait:600" --do "shot:after"
  ```

## 3. Playtest interactive stations/apps

For Farm stations (or any page with a `?debug` `window.__farm` / `window.__toybox` hook):
```bash
node tools/playtest.js <page.html>
```
Verify it completes every step without errors or stuck states.

## 4. Environment tips

- If Playwright is installed globally, prefix with `NODE_PATH=$(npm root -g)`.
- If bundled Chromium isn't installed, pass `CHANNEL=chrome`.
- If ESLint 9 + `globals` are installed outside the repo, pass `NODE_PATH=/tmp/toybox-lint/node_modules`.

## 5. After pushing to `main`

- Check the GitHub Actions **Deploy to GitHub Pages** workflow:
  - `check` job (blocking): must be green for the deploy to publish.
  - `report` job (non-blocking): runs `tools/fit.js` (cut-off labels) and `tools/buttons.js` (dead buttons) on changed pages. Inspect its summary and logs (`gh run view --log`) and fix any real issues in a follow-up commit.
